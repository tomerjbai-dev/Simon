# תוכנית — Milestone 4: שיא אישי, מסך אודות וביטול משחק

**מקורות:** `PRD.md` (זרימות 2–3, FR-05, FR-07, Edge Cases), `DESIGN.md` (סרגל עליון, 1.5, 1.6, 2.3), `ARCHITECTURE.md` (2.3, 2.4, 2.6, 2.7, ADR-2, ADR-4, ADR-7).
**מצב קיים:** משחק מלא של 10 שלבים (Milestone 3). בסרגל העליון יש כפתור השתקה משמאל ומקום שמור ריק מימין (`span.top-bar-slot`, ADR-2). `GameState.screen` כבר קיים (`'home' | 'about'`) אך לא בשימוש.

## 1. מה נבנה (תמונה כללית)

1. **שמירת שיא אישי** — מודול חדש וטהור (ללא DOM) שקורא וכותב ערך אחד ל-`localStorage`, ושורד כל תקלה.
2. **כפתור "אודות"** — כפתור אייקון "i" שתופס את המקום השמור בפינה הימנית העליונה.
3. **מסך "אודות"** — מסך שני באותו דף HTML (החלפת View, ללא Router), עם תיאור, הוראות, ניקוד, שיא אישי וכפתור "חזרה למשחק".
4. **ביטול משחק** — פונקציה טהורה אחת (`abandonGame`) שמשמשת גם למעבר ל"אודות" וגם למעבר הדף לרקע; מנקה Timers וצלילים ומחזירה למצב התחלתי, בלי לגעת בשיא.

## 3. שיא אישי — `src/highScore.ts`

```ts
export const HIGH_SCORE_KEY = 'simon.highScore.v1';
export type HighScoreStore = { get(): number; record(score: number): number };
export function createHighScoreStore(storage: StorageLike | null): HighScoreStore;
export function getLocalStorage(): StorageLike | null; // try/catch — accessing window.localStorage itself can throw
```
- `StorageLike` = `Pick<Storage, 'getItem' | 'setItem'>`, כדי לבדוק עם אחסון מזויף בסביבת `node`.
- **קריאה (`get`)**: `try/catch`; הערך חייב להיות מחרוזת של מספר שלם בטווח `0..55` (`MAX_SCORE` = 55, מחושב מ-`TOTAL_LEVELS`). אחרת — 0. ("abc", "3.5", "-1", "99", ריק, `null` → 0.)
- **שמירה (`record(score)`)**: מחשב `max(get(), score)`; כותב **רק** אם `score` גבוה מהשיא הקיים; כשל כתיבה נבלע. מחזיר את השיא העדכני.
- **אחסון לא זמין**: נשמר שיא זמני בזיכרון (משתנה מקומי), כך שבאותה פתיחת דף המסך "אודות" עדיין מציג את השיא שהושג (ARCHITECTURE 2.7: "שיא זמני להצגה"). אחרי רענון הוא אובד — כמצופה.
- הקריאה נעשית בכל פתיחה של "אודות" (לא נשמרת ב-`GameState`), כך שהמסך תמיד מציג את הערך העדכני.

## 4. לוגיקת משחק — `src/game.ts` (פונקציות טהורות)

- `abandonGame(state)`: מחזיר `phase: 'idle'`, `level: 0`, `score: 0`, `sequence: []`, `nextInputIndex: 0`, **`runId + 1`** (כדי שכל Callback ישן ייפסל), ושומר `muted` ו-`screen`. אם כבר `idle` — מחזיר את אותו State.
- `openAbout(state)`: `abandonGame` + `screen: 'about'`.
- `closeAbout(state)`: `screen: 'home'` (המשחק כבר `idle`).
- `abandonGame` לא מכיר את השיא בכלל — כך "אין עדכון שיא" מובטח במבנה, ולא רק בזהירות.

## 5. חיבור — `src/app.ts`

- `createApp(root, audio, highScore)`.
- **שמירת שיא**: ב-`onTile`, מיד כש-`result` הוא `'wrong'` או `'won'` — `highScore.record(next.score)`. השמירה מתבצעת ברגע הסיום עצמו (לפני הופעת הכרטיס), כי המשחק כבר הסתיים. זה המקום היחיד שקורא ל-`record`, ו-`pressColor` מחזיר `'wrong'`/`'won'` רק פעם אחת לכל משחק → לכל היותר שמירה אחת לכל סיום.
- **`leaveGame()`** (פנימי): `clearPending()`, ניקוי הארה/הצלחה/כרטיס תוצאה (כמו ב-`onStart`), ואז `setState(abandonGame(state))`.
- **`onAbout()`**: `leaveGame()` → `setState(openAbout(state))` → `ui.setHighScore(highScore.get())`.
- **`onBack()`**: `setState(closeAbout(state))` — מסך בית במצב התחלתי עם "התחל".
- **מעבר לרקע**: `document.addEventListener('visibilitychange', ...)` כאשר `visibilityState === 'hidden'`, וגם `window.addEventListener('pagehide', ...)` כגיבוי → `leaveGame()`. בחזרה לא מופעל דבר.
  - משחק "פעיל" = `presenting` / `input` / `stageSuccess`. אם המשחק כבר הסתיים (`lost`/`won`), מעבר לרקע **לא** מאפס את כרטיס התוצאה (ה-PRD מדבר על "משחק פעיל"; השיא כבר נשמר). מעבר ל"אודות" כן מאפס תמיד — FR-07: החזרה מציגה מסך התחלתי.
- **רענון**: אין קוד מיוחד — `GameState` בזיכרון בלבד, והשיא נקרא מחדש מ-`localStorage`. אין `beforeunload`/`unload`.
- מצב ההשתקה נשמר בזיכרון בין המסכים (לא ב-`localStorage`).

## 6. ממשק — `src/ui.ts`, `src/icons.ts`, `src/format.ts`, `src/styles.css`

### כפתור "אודות"
- `span.top-bar-slot` מוחלף ב-`button.icon-btn` עם `ICON_INFO` (עיגול עם "i", באותו סגנון קווי של אייקוני הרמקול), `aria-label="אודות"`. הסרגל נשאר `dir="ltr"` — השתקה בשמאל, "אודות" בימין (DESIGN, סרגל עליון).
- הכפתור פעיל בכל מצבי מסך הבית, כולל בזמן הצגת רצף (שם מתרחש ביטול המשחק).

### מסך "אודות"
- `section.about` נבנה פעם אחת ב-`mountUi` (ADR-7), אחות של `main.screen` הקיים; `update(state)` מסתיר אחד ומציג את השני לפי `state.screen`. גלילה אנכית מותרת במסך זה בלבד אם הטקסט ארוך ממסך הטלפון; ללא גלילה אופקית.
- בעת פתיחה: גלילה לראש המסך, ומעבר פוקוס לכותרת (נגישות בסיסית).
- מבנה (מלמעלה למטה), באותה שפת Surface (`.card`), רדיוס, מרווחים וטיפוגרפיה:
  1. כותרת **"אודות"** — H1 (32px Bold), ממורכזת, באותו סגנון של "סיימון".
  2. כרטיס **"שיא אישי"** — תווית Caption (14px, Text Secondary) + מספר גדול. בלי שיא: הטקסט "עדיין אין שיא" (PRD: "מוצג מצב ללא שיא קודם").
  3. כרטיס **"מה זה סיימון?"** — H3 + פסקה (Body 16px).
  4. כרטיס **"איך משחקים"** — H3 + רשימה ממוספרת.
  5. כרטיס **"ניקוד"** — H3 + רשימה.
  6. כפתור **"חזרה למשחק"** — Secondary Button ברוחב מלא (DESIGN 2.3).
- אין סרגל עליון ואין כפתור השתקה במסך זה (שני כפתורי הסרגל מוגדרים למסך הבית בלבד).
- כל הטקסט ב-`textContent` (ללא `innerHTML`), RTL, מיושר לימין; כותרות ממורכזות.

### טקסטים מוצעים (נגזרים מה-PRD — מבקש את אישורך או תיקון לפני הבנייה)

**מה זה סיימון?**
סיימון הוא משחק זיכרון: המשחק מציג רצף של אורות וצלילים, ועליך לחזור עליו בדיוק באותו הסדר.

**איך משחקים**
1. לוחצים על "התחל".
2. צופים ברצף הצבעים ומקשיבים לצלילים. בזמן ההצגה אי אפשר ללחוץ.
3. לוחצים על הצבעים באותו הסדר. אין מגבלת זמן.
4. בכל שלב מוצג רצף חדש, ארוך בצבע אחד מהקודם ומהיר יותר.
5. טעות אחת מסיימת את המשחק. אחרי 10 שלבים — ניצחת!

**ניקוד**
- כל שלב שמושלם מזכה בנקודות כמספר השלב: שלב 1 — נקודה אחת, שלב 10 — 10 נקודות.
- הניקוד המרבי הוא 55.
- השיא האישי נשמר במכשיר הזה בלבד, ומתעדכן בסיום משחק כשמשיגים ניקוד גבוה יותר.
- יציאה באמצע משחק (מעבר לאודות, רענון או מעבר לאפליקציה אחרת) מבטלת את המשחק בלי לשמור את הניקוד.

### `format.ts`
`TEXT` מקבל: `about: 'אודות'`, `back: 'חזרה למשחק'`, `highScore: 'שיא אישי'`, `noHighScore: 'עדיין אין שיא'`, וכותרות הסעיפים. הטקסטים הארוכים של מסך אודות יישבו בקבוע `ABOUT_TEXT` באותו קובץ.
`formatHighScore(n)`: `0` → `'עדיין אין שיא'`, אחרת `String(n)` (ניקוד 0 לעולם לא נשמר כשיא, ולכן 0 = אין שיא).

### `Ui` API
מתווספים `onAbout`, `onBack` ל-`UiHandlers`, ו-`setHighScore(value: number)` ל-`Ui`.

## 7. ADRs להוספה ל-ARCHITECTURE.md

- **ADR-11: שמירת השיא ברגע הסיום** — `record` נקרא רק ב-`app.ts` כש-`pressColor` מחזיר `wrong`/`won`, לפני הופעת הכרטיס; `abandonGame` לא נוגע בשיא. גיבוי בזיכרון כש-`localStorage` חסום.
- **ADR-12: ביטול משחק אחד לכל סוגי היציאה** — `abandonGame` מגדיל `runId`; מעבר לרקע מבטל רק משחק פעיל, ו"אודות" מאפס תמיד. `visibilitychange` + `pagehide`, ללא `beforeunload`. מחליף את ADR-2 (המקום השמור מתמלא).
- **ADR-13: מסך אודות כ-View שני באותו DOM** — נבנה פעם אחת ומוסתר/מוצג לפי `state.screen`; ללא Router וללא שינוי כתובת.

## 8. בדיקות אוטומטיות (Vitest, סביבת `node`)

**`highScore.test.ts`** (אחסון מזויף מבוסס `Map`):
- אין ערך → 0; ערכים פגומים ("abc", "3.5", "-1", "56", "") → 0; "55" → 55.
- `record` של תוצאה גבוהה כותב; תוצאה נמוכה או שווה לא כותבת ולא דורסת.
- `getItem` / `setItem` שזורקים שגיאה → אין קריסה; `get` מחזיר 0 או את השיא הזמני.
- אחסון `null` → השיא הזמני בזיכרון עובד בתוך אותה פתיחה.
- שמירה מחזירה את המפתח `simon.highScore.v1` ומחרוזת מספר שלם.

**`game.test.ts`**:
- `abandonGame` מכל מצב פעיל → `idle`, שלב 0, ניקוד 0, רצף ריק, `runId` גדל, `muted` נשמר.
- `abandonGame` על `idle` → ללא שינוי.
- `finishPresenting` עם ה-`runId` הישן אחרי ביטול → ללא השפעה (Callback ישן נפסל).
- `pressColor` אחרי ביטול → `ignored`.
- `openAbout` באמצע משחק → `screen: 'about'`, `idle`; `closeAbout` → `screen: 'home'`, `idle`.
- תרחיש משולב: משחק עם ניקוד 3 → `openAbout` → השיא לא השתנה (עם `HighScoreStore` מזויף).

**`state.test.ts`**: `formatHighScore(0)` / `formatHighScore(21)`.

## 9. בדיקה ידנית בזמן הבנייה (דפדפן מחשב, תצוגת טלפון)

1. כפתור "i" בפינה הימנית העליונה, רמקול בשמאלית; הלוח לא זז לעומת Milestone 3.
2. "אודות" → מסך אודות בעברית, "עדיין אין שיא"; "חזרה למשחק" → מסך התחלתי עם "התחל".
3. הפסד עם ניקוד > 0 → "אודות" מציג את הניקוד כשיא. משחק נוסף עם ניקוד נמוך יותר → השיא לא משתנה.
4. מעבר ל"אודות" באמצע הצגת רצף ובאמצע תור שחקן → אין צלילים או הארות אחרי המעבר; השיא לא משתנה; בחזרה — "התחל".
5. רענון באמצע משחק → מצב התחלתי; השיא נשאר.
6. הדמיית מעבר לרקע (`visibilitychange`, למשל מעבר לשונית) באמצע משחק → בחזרה מצב התחלתי, בלי Timers ממשיכים.
7. ערך פגום ב-`localStorage` (נכתב ידנית ב-DevTools) → "עדיין אין שיא", המשחק עובד.
8. רוחב 360px: אין גלילה אופקית במסך הבית ובמסך אודות.
9. `npm run typecheck`, `npm test`, `npm run build` — ללא שגיאות.
