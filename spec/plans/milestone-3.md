# תוכנית — Milestone 3: עשרה שלבים, ניקוד וניצחון

**מקורות:** `MILESTONES.md` (Milestone 3), `PRD.md` (FR-01–FR-04, זרימה 1), `ARCHITECTURE.md` (§2.3–2.5, ADR-4–ADR-8), `DESIGN.md` (§1.2–1.4), `mockups.png`, והקוד הקיים מ-Milestone 2.

## 0. דרישות מוקדמות

- אין צורך במפתחות, חשבונות או `.env`.
- אין תלויות חדשות. אנימציית החגיגה נכתבת ב-CSS בלבד (ללא ספרייה).

## 1. היקף — מה נכלל ומה לא

**נכלל:**
- מעבר אוטומטי לשלב הבא אחרי שחזור נכון של שלב 1–9: משוב הצלחה קצר (כל ארבעת האריחים זוהרים יחד, כמו היום) → השהיה → הצגת הרצף של השלב הבא. בלי כפתור מעבר. זה מחליף את העצירה הזמנית אחרי שלב 1 (ADR-6).
- רצף **חדש ועצמאי** בכל שלב, באורך מספר השלב (שלב `n` → `n` צבעים), שאינו ממשיך את רצף השלב הקודם.
- קצב הצגה לפי שלב: 1000ms בשלב 1 עד 400ms בשלב 10, בהתקצרות אחידה (הפונקציה `flashDurationForLevel` כבר קיימת; עכשיו היא תופעל לכל שלב).
- ניקוד מצטבר: השלמת שלב `n` מוסיפה `n` נקודות; פס הסטטוס מציג "שלב X מתוך 10" ו"ניקוד: Y" ומתעדכן בכל שלב.
- ניצחון אחרי שלב 10: מצב `won` עם כרטיס התוצאה הקיים — כותרת "ניצחת!", "הניקוד שלך" 55, אנימציית חגיגה וכפתור "משחק חדש", **בלי** שורת "הגעת לשלב". באותו מסך, בלי מסך נוסף.
- מניעת מעבר לשלב 11.

**לא נכלל (Milestone 4 ואילך):**
- שיא אישי, `localStorage`, מסך "אודות", כפתור "אודות", ביטול משחק במעבר לרקע/רענון.
- צליל ניצחון או צליל שגיאה — לא מוגדרים ב-PRD, ולכן לא יתווספו.
- הודעות טקסט בזמן הצגה/שחזור, Progress Bar — אסורים לפי ה-PRD.

## 3. מנוע המשחק (`game.ts`)

```ts
export type PressResult = 'ignored' | 'correct' | 'stageComplete' | 'won' | 'wrong';

pressColor(state, color)
// כמו היום, אבל בלחיצה הנכונה האחרונה:
//   level < TOTAL_LEVELS → phase 'stageSuccess', score += level, result 'stageComplete'
//   level === TOTAL_LEVELS → phase 'won',         score += level, result 'won'

advanceLevel(state, rng?): GameState
// רק אם phase === 'stageSuccess' ו-level < TOTAL_LEVELS; אחרת מחזיר את state ללא שינוי.
// level + 1; sequence = generateSequence(level + 1, rng) — רצף חדש לגמרי;
// nextInputIndex = 0; phase 'presenting'; score ו-muted נשמרים; runId לא משתנה.
```

- `runId` ממשיך לזהות "משחק" (ולא שלב): הוא גדל רק ב-`startGame`. כך Timer של משחק קודם לא ישפיע על משחק חדש, וטיימרים של אותו משחק ממשיכים לעבוד בין שלבים. `finishPresenting` כבר בודק `runId` ו-`phase === 'presenting'`.
- `TOTAL_LEVELS = 10` מ-`state.ts` הוא המקור היחיד למספר השלבים.

## 4. זמנים (`timing.ts`)

- קבוע חדש: `WIN_REVEAL_DELAY = 700` — משך הזוהר המשותף לפני הופעת כרטיס הניצחון (אותו משך כמו משוב ההצלחה הרגיל).
- ההשהיה בין שלבים היא `SUCCESS_FEEDBACK` (700ms) ואחריה `PRE_PLAYBACK_DELAY` (600ms) לפני הצבע הראשון — סה"כ כ-1.3 שניות. אין שינוי בקבועים הקיימים.
- `flashDurationForLevel` לא משתנה. בגלל עיגול למילישניות, ההפרש בין שלבים הוא 66 או 67ms (1000, 933, 867, 800, 733, 667, 600, 533, 467, 400) — זו ההתקצרות האחידה של 600/9.

## 5. ה-App (`app.ts`)

- פונקציה פנימית חדשה `playLevel()`: מחשבת את משך ההצגה לפי `state.level`, מפעילה את `playSequence` עם בדיקת `runId` (כמו היום ב-`onStart`), ובסיום קוראת ל-`finishPresenting`. `onStart` משתמש בה אחרי `startGame`.
- ב-`onTile`:
  - `stageComplete` → `ui.setSuccess(true)`; אחרי `SUCCESS_FEEDBACK` (דרך `later`, שמוגן ב-`runId`): `ui.setSuccess(false)`, `setState(advanceLevel(state))`, `playLevel()`.
  - `won` → `ui.setSuccess(true)`; אחרי `WIN_REVEAL_DELAY`: `ui.setSuccess(false)`, `ui.setActiveTile(null)`, `ui.showResult(true)`.
  - `wrong` → ללא שינוי.
- "משחק חדש" אחרי ניצחון או הפסד עובר דרך `onStart` הקיים, שמנקה את כל ה-Timers ומגדיל `runId`.
- אין מגבלת זמן בתור השחקן — לא מוסיפים שום Timer בשלב `input`.

## 6. ממשק (`ui.ts`, `format.ts`)

- `format.ts`: `TEXT.won = 'ניצחת!'`.
- כפתור "משחק חדש"/"התחל" מוסתר (שומר מקום, `is-reserved`) גם ב-`stageSuccess` ובמצב `won` לפני הופעת הכרטיס — כלומר מופיע רק ב-`idle` או כשהכרטיס מוצג. זה מחליף את ההתנהגות הזמנית של ADR-6.
- כרטיס התוצאה (ADR-8) משרת את שני מצבי הסיום:
  - `showCard` = (`lost` או `won`) וגם `resultShown`. כש-`phase` אינו `lost`/`won` — `resultShown` מתאפס.
  - `lost`: כותרת "המשחק נגמר", "הגעת לשלב" + ערך, "הניקוד שלך" + ערך (כמו היום).
  - `won`: כותרת "ניצחת!", שורת "הגעת לשלב" והערך שלה מוסתרים (`hidden`), "הניקוד שלך" 55, ו-Class `is-win` על הכרטיס שמפעיל את אנימציית החגיגה.
- שכבת החגיגה: `div.celebration` בתוך הכרטיס (נבנה פעם אחת, לפי ADR-7) עם כ-16 חלקיקי קונפטי קטנים (`span`) בארבעת צבעי המשחק, `aria-hidden="true"`. מוצג רק כשהכרטיס במצב `is-win`.
- בזמן המשחק מוצגים רק פס השלב והניקוד — אין טקסט נוסף.

## 7. עיצוב (`styles.css`)

- סגנון האנימציה לא נקבע ב-DESIGN/PRD ("ייקבע במימוש"), ולכן נבחר סגנון פשוט התואם לשפה העיצובית:
  - **פרץ קונפטי:** החלקיקים מתפזרים מאמצע הכרטיס כלפי חוץ ונופלים בעדינות, בצבעי האריחים (`#4CD964`, `#FF5B57`, `#FFB74D`, `#4DA3FF`), כ-1.6 שניות, וחוזר כל כמה שניות כל עוד הכרטיס מוצג. מיקום וכיוון לכל חלקיק דרך CSS Variables, בלי JavaScript לאנימציה.
  - **כותרת זוהרת:** "ניצחת!" מקבלת פעימת Glow עדינה ב-Accent Glow (`#6EE7FF`), ועליית מספר הניקוד בהופעה (Scale קטן).
  - החלקיקים לא חוסמים לחיצות (`pointer-events: none`) ולא יוצאים מגבולות המסך (אין גלילה אופקית).
  - `prefers-reduced-motion: reduce` → ללא תנועה; נשאר רק הזוהר הסטטי.
- מצב הכרטיס בהפסד לא משתנה.

## 8. בדיקות (Vitest)

**`game.test.ts`:**
- `advanceLevel`: משלב `n` ל-`n+1`, אורך רצף `n+1`, `nextInputIndex = 0`, `phase = 'presenting'`, ניקוד נשמר.
- רצף חדש ועצמאי: עם RNG מוזרק — הרצף של השלב החדש נקבע רק לפי ה-RNG ואינו מתחיל ברצף הקודם; עם RNG קבוע מתקבלות חזרות; כל הצבעים מתוך ארבעת הצבעים.
- `advanceLevel` לא עושה כלום מחוץ ל-`stageSuccess` ולא אחרי `won` — **אין שלב 11**.
- גבול שלב 1: שלב 1 → רצף של צבע אחד, השלמה → 1 נקודה ו-`stageSuccess`.
- גבול שלב 10: השלמת רצף של 10 צבעים → `won`, `result = 'won'`, ניקוד +10; לחיצות אחרי `won` → `ignored`.
- משחק מלא מדומה (לולאה: הצגה → לחיצות נכונות → מעבר) → בדיוק 10 שלבים, ניקוד סופי 55.
- טעות בשלב `k` → `lost`, `level = k`, ניקוד = `1+…+(k-1)` (למשל טעות בשלב 4 → 6).
- `finishPresenting` עם `runId` ישן לא פותח קלט גם אחרי מעבר שלב.

**`playback.test.ts`:**
- `flashDurationForLevel` לכל עשרת השלבים: 1000 בשלב 1, 400 בשלב 10, יורד בכל שלב, וכל הפרש בתוך 1ms מ-600/9.

## 9. בדיקה עצמית בזמן הבנייה (לפני סימון 🟡)

1. `npm run typecheck`, `npm test`, `npm run build` — ללא שגיאות.
2. הרצת `npm run dev` ובדיקה ב-Browser Pane בגודל טלפון:
   - משחק מלא עד הניצחון: סקריפט בדיקה זמני בקונסולה (לא בקוד הפרויקט) שמאזין לאריחים שנדלקים בזמן ההצגה ולוחץ עליהם אחרי שהלוח נפתח — מאמת מעבר אוטומטי בין כל השלבים, פס סטטוס מתעדכן, ניצחון עם "ניצחת!", 55, אנימציה, ללא "הגעת לשלב".
   - הפסד בשלב מאוחר (למשל 3): כרטיס "המשחק נגמר", הגעת לשלב 3, ניקוד 3.
   - לחיצות בזמן הצגה לא משפיעות; "משחק חדש" אחרי ניצחון ואחרי הפסד מתחיל משלב 1 וניקוד 0.
   - צילום מסך של מצב הניצחון; בדיקה שאין גלילה אופקית.
3. סגירת שרת הפיתוח בסיום.

## 11. החלטות מימוש שיתועדו כ-ADR ב-ARCHITECTURE.md

- **ADR-9: מעבר אוטומטי בין שלבים** — מחליף את העצירה הזמנית של ADR-6; `advanceLevel` טהורה, `runId` מזהה משחק ולא שלב; השהיה של 700ms משוב + 600ms לפני הצבע הראשון.
- **ADR-10: אנימציית ניצחון ב-CSS בלבד** — קונפטי בצבעי האריחים + כותרת זוהרת בתוך כרטיס התוצאה הקיים; ללא ספרייה וללא צליל; כיבוד `prefers-reduced-motion`.
