## 0. דרישות מוקדמות

- אין צורך במפתחות, חשבונות או `.env` (אין סודות; האתר סטטי).

## 1. היקף — מה נכלל ומה לא

**נכלל:**
- מנוע משחק (Game Controller) עם מצבים `idle` → `presenting` → `input` → `stageSuccess` / `lost`, והגנה מפני Timers ישנים באמצעות `runId`.
- הגרלת רצף באורך מספר השלב (בפועל: שלב 1 → צבע אחד), 25% לכל צבע, חזרות מותרות, עם RNG שניתן להזרקה בבדיקות.
- הצגת רצף (Playback) עם הארת אריח וצליל; נעילת הלוח בזמן ההצגה.
- תור שחקן ללא מגבלת זמן; כל לחיצה מאירה ומשמיעה צליל.
- טעות ראשונה → כרטיס "המשחק נגמר" עם "הגעת לשלב", "הניקוד שלך" וכפתור "משחק חדש".
- כפתור השתקה/ביטול השתקה בפינה השמאלית העליונה; ההארה ממשיכה גם במצב מושתק.
- פתיחת השמע (`AudioContext`) מתוך הלחיצה על "התחל" / "משחק חדש".

**התנהגות זמנית אחרי הצלחה בשלב 1 (לפי החלטת המשתמש):** לאחר שחזור נכון של שלב 1 — משוב הצלחה קצר (כל ארבעת האריחים זוהרים יחד לרגע), הניקוד עולה ל-1, המשחק עוצר במצב `stageSuccess`, ומופיע מתחת ללוח כפתור "משחק חדש". **אין** מעבר אוטומטי לשלב 2 ואין כרטיס סיום. ב-Milestone 3 ההתנהגות הזו תוחלף במעבר אוטומטי לשלב הבא.

**לא נכלל:**
- מעבר בין שלבים, קצב משתנה בין שלבים, מצב ניצחון ואנימציית חגיגה (Milestone 3). פונקציית משך ההצגה לפי שלב תמומש כבר עכשיו (נחוצה גם לשלב 1), אבל רק שלב 1 בשימוש.
- כפתור "אודות", מסך אודות, שיא אישי, ביטול משחק במעבר לרקע (Milestone 4). המקום של "אודות" בפינה הימנית של הסרגל העליון נשאר ריק.
- צליל שגיאה מיוחד — לא מוגדר ב-PRD, ולכן לא יתווסף.
- שמירת מצב ההשתקה בין רענונים — ARCHITECTURE §2.4 קובע שאין Persist למצב השתקה. ההשתקה נשמרת רק בזיכרון, גם בין משחקים באותה פתיחת דף.

## 3. מנוע המשחק (`game.ts`) — פונקציות טהורות

כל פונקציה מקבלת `GameState` ומחזירה `GameState` חדש (ללא שינוי במקום). אין בהן DOM או Timers, כדי שיהיה קל לבדוק אותן.

```ts
startGame(state, rng?): GameState
// כל phase → 'presenting'; level = 1; score = 0; nextInputIndex = 0;
// sequence = generateSequence(1, rng); runId = state.runId + 1; muted נשמר.

finishPresenting(state, runId): GameState
// רק אם phase === 'presenting' ו-runId תואם → 'input'. אחרת מחזיר את state ללא שינוי.

pressColor(state, color): { state: GameState; result: 'ignored' | 'correct' | 'stageComplete' | 'wrong' }
// phase !== 'input' → 'ignored' (ללא שינוי).
// color === sequence[nextInputIndex]:
//   - לא האחרון → nextInputIndex + 1, result 'correct'.
//   - האחרון → phase 'stageSuccess', score += level, result 'stageComplete'.
// אחרת → phase 'lost' (level נשאר = השלב שבו נעשתה הטעות, score לא משתנה), result 'wrong'.

toggleMute(state): GameState   // הופך את muted בלבד
```

- `COLORS = ['green', 'red', 'yellow', 'blue'] as const` ב-`state.ts` — מקור יחיד לרשימת הצבעים.
- ב-Milestone 2 אין פונקציה למעבר לשלב הבא; `stageSuccess` הוא מצב עצירה. ב-Milestone 3 תתווסף `advanceLevel`.
- "התחל" ו"משחק חדש" קוראים שניהם ל-`startGame`. הגדלת `runId` מבטלת כל Callback של סבב קודם.

## 5. זמנים (`timing.ts`)

| קבוע | ערך | הערה |
|---|---|---|
| `PRE_PLAYBACK_DELAY` | 600ms | המתנה מהלחיצה על "התחל" עד הצבע הראשון, כדי שהשחקן יספיק להסתכל על הלוח |
| `flashDurationForLevel(n)` | `1000 - (n - 1) * (600 / 9)` | ARCHITECTURE §2.5; שלב 1 = 1000ms |
| `GAP_BETWEEN_FLASHES` | 250ms | הפסקה כבויה בין צבעים, כדי שאותו צבע פעמיים ייראה כשני הבהובים |
| `PRESS_FLASH` | 250ms | משך הארה וצליל בלחיצת שחקן |
| `SUCCESS_FEEDBACK` | 700ms | זוהר משותף של כל האריחים אחרי הצלחה |
| `LOSS_REVEAL_DELAY` | 300ms | זמן קצר שבו רואים את הלחיצה השגויה לפני שכרטיס הסיום מופיע |

ה-PRD מציין שמשכי ההשהיה האלה אינם מוגדרים ונקבעים במימוש. ייבחנו בעין בזמן הבנייה ויתועדו כ-ADR.

## 6. Playback (`playback.ts`)

```ts
playSequence(sequence, flashMs, hooks: { onFlashStart(color), onFlashEnd(color), onDone() }): () => void
// מחזיר פונקציית cancel שמנקה את כל ה-Timers שנקבעו.
```
- תזמון: `PRE_PLAYBACK_DELAY`, ואז לכל צבע: `onFlashStart` → אחרי `flashMs` `onFlashEnd` → `GAP` → הצבע הבא; אחרי האחרון `onDone`.
- שימוש ב-`setTimeout` בלבד; כל ה-Timer IDs נשמרים כדי לבטל אותם.
- נבדק עם `vi.useFakeTimers()`: סדר ה-Callbacks, תזמון, וש-`cancel` מונע כל Callback נוסף.

## 7. שמע (`audio.ts`)

- `createAudio()` מחזיר אובייקט עם: `unlock()`, `play(color, durationMs)`, `stopAll()`.
- `unlock()` נקרא **בתוך** Handler של הלחיצה על "התחל"/"משחק חדש": יוצר `AudioContext` בפעם הראשונה וקורא ל-`resume()` (גם אם נעצר בינתיים). הכל עטוף ב-`try/catch` — כשל שמע לא עוצר את המשחק.
- כל צליל: `OscillatorNode` (`triangle`) → `GainNode` עם Envelope קצר (עלייה ~10ms, דעיכה ~60ms בסוף) כדי למנוע "קליקים".
- תדירויות קבועות, מובחנות היטב (בהשראת Simon המקורי):

| צבע | תדירות |
|---|---|
| ירוק | 415 Hz |
| אדום | 310 Hz |
| צהוב | 252 Hz |
| כחול | 209 Hz |

- השתקה: ה-App פשוט לא קורא ל-`play` כש-`muted`; לחיצה על השתקה בזמן צליל קורא ל-`stopAll()`. ההארות לא מושפעות.

## 8. ה-App (`app.ts`) — חיבור הכל

- מחזיק את ה-`state` הנוכחי, את ה-`cancel` של ה-Playback ואת ה-Timers הפעילים (הצלחה / חשיפת כרטיס סיום / כיבוי הארת לחיצה).
- **"התחל" / "משחק חדש":** `audio.unlock()` → ביטול כל Timer/Playback קיים → `startGame` → `ui.update` → `playSequence(...)`. כל Callback בודק `runId === state.runId` לפני שהוא עושה משהו (שכבת הגנה שנייה מעבר ל-cancel).
- **onFlashStart/End:** `ui.setActiveTile(color | null)` + `audio.play` (אם לא מושתק).
- **onDone:** `finishPresenting` → הלוח נפתח לקלט.
- **לחיצה על אריח:** `pressColor`. אם `ignored` — לא קורה כלום (גם לא הארה וצליל, כי הלוח נעול). אחרת: הארה + צליל ל-`PRESS_FLASH`, ואז:
  - `correct` — ממשיכים להמתין ללחיצה הבאה (ללא מגבלת זמן).
  - `stageComplete` — אחרי סיום הארת הלחיצה: זוהר הצלחה `SUCCESS_FEEDBACK`, עדכון ניקוד, הצגת "משחק חדש".
  - `wrong` — ה-state הופך מיד ל-`lost` (לחיצות נוספות נזנחות), וכרטיס הסיום מוצג אחרי `LOSS_REVEAL_DELAY`.
- **לחיצות מהירות:** כל `click` מטופל בנפרד ובסדר הגעתו; לחיצה כפולה על אותו צבע = שתי לחיצות (אין מיזוג). הארת לחיצה חדשה מחליפה את הקודמת.
- **השתקה:** `toggleMute` → עדכון אייקון ותווית; אם הושתק — `audio.stopAll()`.

## 9. ממשק (`ui.ts`, `icons.ts`, `format.ts`)

**שינוי גישה:** במקום לבנות את כל המסך מחדש בכל שינוי, ה-DOM נבנה פעם אחת (`mountUi(root, handlers)`), ו-`update(state)` מעדכן רק טקסטים, Classes ונראות. כך האריחים לא נבנים מחדש באמצע לחיצה, וההארות לא נקטעות.

**לפי מצב:**

| phase | אזור עליון | אמצע | למטה |
|---|---|---|---|
| `idle` | כותרת "סיימון" | לוח (פעיל ויזואלית, לחיצה לא עושה כלום) | "התחל" |
| `presenting` | פס "שלב 1 מתוך 10 \| ניקוד: 0" | לוח נעול: אריחים לא פעילים מעומעמים מעט; האריח המוצג זוהר | אזור הכפתור שומר מקום אך מוסתר (`visibility: hidden`) כדי שהלוח לא יזוז |
| `input` | אותו פס | לוח פתוח, באותו גודל ומיקום | מוסתר (שומר מקום) |
| `stageSuccess` | פס עם "ניקוד: 1" | לוח, זוהר הצלחה קצר ואז רגיל ונעול | "משחק חדש" |
| `lost` | — | כרטיס סיום במקום הפס והלוח (לפי ה-Wireframe) | "משחק חדש" |

**כרטיס סיום (`lost`):** Surface כהה-שקוף ומעוגל (סגנון `.card` הקיים):
- כותרת "המשחק נגמר" (H2, 24px Bold).
- "הגעת לשלב" (Body/Large 18px Medium) ומתחתיו המספר בגדול (~56px Bold).
- "הניקוד שלך" ומתחתיו הניקוד בגדול.
- **ללא** כרטיס "שיא אישי" (DESIGN §1.4).
- נוסחי ה-PRD בלבד: "המשחק נגמר", "משחק חדש" (ולא "המשחק הסתיים" / "התחל מחדש" שבתמונות).

**סרגל עליון:**
- כפתור אייקון עגול (~44px, רקע כהה, גבול דק, אייקון לבן) בפינה **השמאלית** העליונה. הפינה הימנית נשארת ריקה (שמורה ל"אודות" ב-Milestone 4). בגלל ה-RTL, המיקום ייקבע במפורש ב-CSS כדי שלא יתהפך.
- אייקון רמקול כשהשמע פעיל, רמקול עם קו/X כשמושתק — SVG פשוט בתוך הקוד (ללא קבצים או ספריות).
- `aria-label`: "השתק צלילים" (כשהשמע פעיל) / "הפעל צלילים" (כשמושתק), ו-`aria-pressed` לפי `muted`.
- מוצג בכל המצבים ולא זז.

**לוח:**
- בזמן `presenting` / `stageSuccess` / `lost` האריחים מקבלים `disabled` (הגנה נוספת מלבד המנוע). ב-`idle` ו-`input` הם פתוחים ללחיצה.
- הארה דרך Class `is-active` (כבר קיים ב-CSS מ-Milestone 1).
- `aria-label` בעברית נשאר ("ירוק", "אדום"...).

**טקסטים חדשים ב-`format.ts`:** `"המשחק נגמר"`, `"הגעת לשלב"`, `"הניקוד שלך"`, `"משחק חדש"`, `"התחל"`, `"השתק צלילים"`, `"הפעל צלילים"`.

**אין** טקסט הנחיה מתחלף (כמו "תורך!") ואין Progress Bar.

## 11. בדיקות (Vitest)

- `sequence.test.ts`:
  - אורך הרצף = הפרמטר (1, 5, 10).
  - כל הצבעים מתוך `COLORS` בלבד.
  - RNG מוזרק: `0, 0.25, 0.5, 0.75` → `green, red, yellow, blue` — ארבע אפשרויות.
  - RNG קבוע `0.1` → כל הרצף אותו צבע (חזרות מותרות).
  - ערך גבולי `0.9999` → כחול, ללא חריגה מהמערך.
- `game.test.ts`:
  - `startGame` → `presenting`, שלב 1, ניקוד 0, רצף באורך 1, `runId` גדל, `muted` נשמר.
  - `pressColor` ב-`presenting` / `idle` / `lost` / `stageSuccess` → `ignored` ללא שינוי.
  - `finishPresenting` עם `runId` ישן → אין שינוי; עם `runId` נכון → `input`.
  - לחיצה נכונה בשלב 1 → `stageSuccess`, ניקוד 1.
  - לחיצה שגויה → `lost`, `level` נשאר 1, ניקוד 0.
  - רצף `['red', 'red']` (מוזרק ישירות ל-state): לחיצה אחת על אדום → `correct` ועדיין `input` עם `nextInputIndex = 1`; שנייה → `stageComplete` (אין מיזוג).
  - רצף `['red', 'blue']`: אדום ואז ירוק → `wrong` באמצע הרצף.
  - `startGame` מתוך `lost` → מאפס ניקוד ושלב, `runId` חדש.
  - `toggleMute` הופך רק את `muted`.
- `playback.test.ts` (Fake Timers): סדר `onFlashStart/onFlashEnd/onDone` וזמנים; אותו צבע פעמיים מייצר שני זוגות start/end עם הפסקה ביניהם; `cancel()` באמצע → אין Callbacks נוספים.
- `timing.test.ts`: `flashDurationForLevel(1) === 1000`, `flashDurationForLevel(10) === 400`.
- `state.test.ts`: `COLORS` מכיל בדיוק ארבעה צבעים שונים.
- `audio.ts` ו-`ui.ts` תלויים בדפדפן — נבדקים ידנית (סעיף 12), ללא הוספת jsdom.
